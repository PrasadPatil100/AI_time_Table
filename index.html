Technology Stack

Built on MongoDB for Scalable Academic Data

Our architecture leverages MongoDB's flexible document model to store multi-department schedules, JSON-based time slots, and atomic conflict validation rules. Built for performance at any scale.

  • Document-Based Storage – Store complete timetable objects with nested subjects, faculty, and rooms in a single MongoDB document.
  • Atomic Conflict Validation – Use MongoDB transactions and unique indexes to ensure zero double-bookings at the database level.
  • JSON Time Slots – Native JSON arrays for time slots enable fast querying and real-time schedule aggregation across departments.
  • Horizontal Scalability – Shard-ready architecture supports unlimited departments, classes, and institutions on MongoDB Atlas.

// Sample Timetable Document Schema
const TimetableSchema = new mongoose.Schema({
  className: { type: String, required: true },
  department: { type: String, required: true },
  timeSlots: [
    {
      day: String,
      startTime: String,
      endTime: String,
      subject: { type: mongoose.Schema.Types.ObjectId, ref: 'Subject' },
      faculty: { type: mongoose.Schema.Types.ObjectId, ref: 'Faculty' },
      room: String,
      isLunch: { type: Boolean, default: false }
    }
  ],
  createdAt: { type: Date, default: Date.now }
});

// Unique compound index prevents conflicts
TimetableSchema.index(
  { className: 1, day: 1, startTime: 1 },
  { unique: true }
);
